# GeoCore Academy — Руководство по биллингу и аккаунтам Moodle

> Реализовано: 2026-04-21 (сессия 15)  
> Охватывает: счета на оплату, подтверждение платежей, выдача аккаунтов Moodle, email-уведомления

---

## Архитектура потока

```
Заявка (форма) → Админка → [Указать сумму] → [Сформировать счёт PDF+QR]
                         → [Отметить оплаченным]
                              ↓ автоматически
                         Создать аккаунты Moodle + Отправить email клиенту
                              ↓ вручную (если нужно повторно)
                         [Кнопка «Отправить клиенту ✉»]
```

## Что проверить после перезапуска контейнера бэкенда

После `docker compose up -d --force-recreate backend` или обновления через CI/CD:

```bash
# 1. Контейнер запущен
docker ps | grep geocore_api

# 2. API отвечает
curl https://api.geocore-academy.ru/api/health

# 3. MOODLE_TOKEN актуален (ключ не должен быть «недействителен»)
curl https://api.geocore-academy.ru/api/courses

# 4. Логи без ошибок запуска
docker logs geocore_api --tail 20
```

### Если `/api/courses` возвращает «Ключ недействителен»

Токен сбросился после пересоздания контейнера Moodle. Нужно создать новый:

1. Moodle → **Сервер → Веб-службы → Управление ключами**
2. Удалить старый токен пользователя `geocore_api` → создать новый
3. Скопировать токен в `.env` на VPS: `MOODLE_TOKEN=<новый токен>`
4. Перезапустить бэкенд: `docker compose up -d --force-recreate backend`

### Если аккаунты Moodle не создаются (invalidparameter)

```bash
docker logs geocore_api --tail 50 2>&1 | grep -i "moodle\|error"
```

Причины и решения:

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Ключ недействителен` | Устаревший MOODLE_TOKEN | Обновить токен (см. выше) |
| `invalidparameter` | Неверный параметр API | Проверить версию бэкенда — пересобрать |
| `Пользователь уже существует` | Повторный вызов mark-paid | Игнорировать, зачислить вручную |

### Проверить после деплоя

```bash
# API отвечает
curl https://api.geocore-academy.ru/api/health

# Шрифт для кириллицы в PDF установлен
ssh user@vps "docker exec geocore_api ls /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf"

# Новые колонки созданы
ssh user@vps "docker exec geocore_db mysql -umoodle -p moodle -e 'SHOW COLUMNS FROM requests;'"
# Должны быть: total_price, invoice_status, invoice_link, payment_status, access_expiry_date, moodle_accounts_generated

# Таблица аккаунтов создана
ssh user@vps "docker exec geocore_db mysql -umoodle -p moodle -e 'SHOW TABLES;'"
# Должна быть: moodle_accounts

# Логи запуска без ошибок
ssh user@vps "docker logs geocore_api --tail 30"
```

## Пошаговый тест (полный сценарий)

### Шаг 1 — Создать тестовую заявку

Открыть `geocore-academy.ru` → кнопка «Корпоративное обучение» → заполнить форму:

| Поле | Тестовое значение |
|------|------------------|
| Курс | Введение в геологию |
| Компания | ООО Тест |
| ИНН | 1234567890 |
| Email для договора | ваш@email.com |
| Количество сотрудников | 2 |
| Сотрудник | Иванов Иван |
| Email сотрудника | ivan@test.com |

→ Нажать **Отправить заявку**

Ожидаемый результат: на `ваш@email.com` придёт авто-ответ «Заявка принята».

---

### Шаг 2 — Войти в админку

`geocore-academy.ru/frontend/admin.html` → логин + токен → **Войти**

Найти только что созданную заявку в таблице.  
Новые колонки: **Сумма** (—), **Счёт** (—), **Оплата** (—).

---

### Шаг 3 — Открыть модальное окно

Нажать **✎** в строке заявки.

Что проверить в модалке:
- Компания, ИНН, курс отображаются корректно
- Поля «Количество участников» и «Стоимость» редактируемы

---

### Шаг 4 — Заполнить сумму и сохранить

В модалке:
- **Количество участников**: 2
- **Стоимость**: 15000
- Нажать **Сохранить**

Ожидаемый результат: toast «Сохранено», в таблице в колонке **Сумма** появится `15000 ₽`.

---

### Шаг 5 — Сформировать счёт

В модалке нажать **«Сформировать счёт»**.

Ожидаемый результат:
- Появятся ссылки 📄 Счёт PDF и 🔲 QR-код
- Статус счёта: «✓ создан»
- В таблице колонка **Счёт** покажет бейдж «Создан» (синий)

Открыть PDF — проверить:
- Номер счёта = ID заявки
- Компания, ИНН, курс, сумма заполнены
- Кириллица отображается (если `fonts-dejavu-core` установлен)
- Тестовые реквизиты присутствуют

Открыть QR — проверить что картинка загружается (тестовый, не СБП).

**Ошибка «Сначала укажите стоимость»** — значит шаг 4 не был выполнен.

---

### Шаг 6 — Подтвердить оплату

В модалке нажать **«Отметить оплаченным»** → подтвердить в confirm-диалоге.

Ожидаемый результат:
- Статус оплаты в модалке: «✓ оплачен» (зелёный)
- Кнопка «Отметить оплаченным» скрыта
- В таблице колонка **Оплата** покажет бейдж «Оплачен» (зелёный)
- Статус строки в таблице: «Оплачена»
- В разделе **Аккаунты Moodle** появятся логины/пароли
- На `contact_email` заявки автоматически отправится письмо

Проверить логи:
```bash
docker logs geocore_api --tail 20 -f
```

Что должно быть в логах:
```
[moodle] Ошибка создания пользователя: ...   # если MOODLE_TOKEN не настроен
# или
[email] Аккаунты → client@email.com          # письмо отправлено
```

---

### Шаг 7 — Повторная отправка аккаунтов вручную

В модалке, в разделе «Аккаунты Moodle», нажать **«Отправить клиенту ✉»**.

Ожидаемый результат: toast «Письмо отправлено → client@email.com».

Использовать когда:
- Клиент не получил первое письмо (попало в спам)
- Нужно отправить другому контакту (сначала поменять email вручную в БД)
- Первая отправка упала по ошибке SMTP

## Moodle API — требования к токену

Если `MOODLE_TOKEN` не настроен — аккаунты не создаются, но всё остальное (статус, PDF, email-заглушка) работает.

Для полной интеграции нужен токен с функциями:

1. Администрирование Moodle → Плагины → Web services → Включить
2. Управление протоколами → REST → Включить
3. Управление внешними сервисами → Добавить сервис → Добавить функции:
   - `core_user_create_users`
   - `enrol_manual_enrol_users`
   - `core_course_get_courses`
4. Управление токенами → Создать токен → скопировать в `.env` → `MOODLE_TOKEN=...`

Зачисление происходит на курс, `fullname` которого содержит название из заявки (без учёта регистра).  
Пример: заявка «Введение в геологию» → ищет Moodle-курс с `fullname` содержащим «введение в геологию».

## Известные ограничения (заглушка, этапы 1–3)

| Что | Ограничение | Решение в будущем |
|-----|------------|-------------------|
| Хранение PDF/QR | `/app/static/` в контейнере, теряются при `--force-recreate` | Смонтировать volume или S3 |
| QR-код | Тестовый текст, не СБП | После открытия счёта в банке — генерация по стандарту СБП |
| Счёт | Тестовые реквизиты | После открытия ИП/ООО — подставить реальные |
| Проверка оплаты | Только ручная (кнопка в админке) | API выписок банка (Тинькофф / Сбер) |
| Поиск курса Moodle | По подстроке названия | Маппинг course_name → moodle_course_id в site.json |

## Эндпоинты API (справка)

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/api/admin/requests/{id}` | Одна заявка + аккаунты |
| `PATCH` | `/api/admin/requests/{id}/headcount?headcount=2` | Обновить количество |
| `PATCH` | `/api/admin/requests/{id}/total_price?total_price=15000` | Обновить сумму |
| `POST` | `/api/admin/requests/{id}/generate-invoice` | Сформировать PDF + QR |
| `POST` | `/api/admin/requests/{id}/mark-paid` | Подтвердить оплату + создать аккаунты |
| `POST` | `/api/admin/requests/{id}/send-accounts` | Повторно отправить аккаунты клиенту |

Все эндпоинты требуют `Authorization: Bearer <ADMIN_TOKEN>` и `X-Admin-User: <ADMIN_USERNAME>`.
