# Архитектурные решения

> Почему сделано именно так. Читать перед тем как что-то менять.

---

## nginx на хосте, не в Docker

**Решение:** nginx остаётся на хосте VPS, не в контейнере.  
**Почему:** Проще управлять SSL-сертификатами Let's Encrypt (certbot работает напрямую с хостом). Меньше сложности с проксированием сокетов.  
**Когда принято:** Сессия 2026-04-07.

---

## Теги Docker: версия + ревизия

**Решение:** Формат тегов `{версия}-r{N}` (например `geocore-moodle:5.1.3-r1`).  
**Почему:** Позволяет отличать наши правки от upstream-версии Moodle. При обновлении Moodle — меняется версия, при нашем хотфиксе — N.

---

## Moodle: данные в volume, не в контейнере

**Решение:** moodledata и БД — в Docker volumes.  
**Почему:** При обновлении образа данные сохраняются. `upgrade.php` обновляет только схему БД.  
**Важно:** Никогда не делать `docker compose down -v` на production — это сотрёт все данные.

---

## Frontend: статические данные в site.json + siteRenderer.js

**Решение:** nav, курсы (анонсы), футер — в `site.json`. Рендеринг — `siteRenderer.js`.  
**Почему:** Один источник правды для всех страниц. Изменение nav/футера — только в одном файле.  
**Трёхуровневые курсы:**
- ОТКРЫТ → курсы из Moodle с SCORM (кликабельные)
- СКОРО → Moodle-курсы без SCORM (некликабельные)  
- В РАЗРАБОТКЕ → из site.json (самые блёклые)

---

## Email: Gmail SMTP как транспорт, Zoho как inbox

**Решение:** Отправка через Gmail SMTP (App Password), получение через Zoho Mail (info@geocore-academy.ru).  
**Почему:** Zoho Free не поддерживает внешний SMTP. Gmail SMTP бесплатен для небольших объёмов.  
**Миграция:** При переходе на платный Zoho — только меняем SMTP_HOST/USER/PASS в `.env`.

---

## Moodle: не трогать без согласования

**Решение:** Любые изменения в `moodle/` — только после явного подтверждения.  
**Почему:** Moodle — работающая production-платформа с данными студентов. Случайный `down -v` или неудачный entrypoint.sh может потребовать переустановки и потери данных.
