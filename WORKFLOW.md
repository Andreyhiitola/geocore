# GeoCore-Academy — Протокол рабочей сессии

---

## Начало сессии

```
1. Прочитать STATUS.md — понять где мы находимся
2. Создать ветку для задачи:
   git checkout -b feat/название-задачи
   или
   git checkout -b fix/что-фиксируем
3. Убедиться что VPS и сервисы живы:
   ssh root@<vps> "docker ps"
```

---

## В процессе работы

```
- Коммитить часто — после каждого завершённого шага
- Хотфиксы и мелкие правки — можно сразу в main
- Крупные фичи — только через ветку → PR → merge в main
```

---

## Конец сессии

```
1. Обновить STATUS.md:
   - Отметить что сделано ✅
   - Обновить "Что осталось"
   - Добавить в "Решённые проблемы" если был баг

2. Записать итог сессии в SESSION_LOG.md:
   Дата, что делали, что решили, что отложили

3. Смёржить ветку в main (если фича готова):
   git checkout main
   git merge feat/название-задачи
   git push origin main
   git branch -d feat/название-задачи

4. Убедиться что CI/CD прошёл на GitHub Actions
```

---

## ⚠️ Приоритеты и ограничения

> **Moodle не трогаем** пока не закончим остальную инфраструктуру.
> Любые изменения в `moodle/` — только после явного согласования.

---

## Правила веток

| Тип | Формат | Когда |
|-----|--------|-------|
| Фича | `feat/название` | новый функционал |
| Фикс | `fix/название` | баг |
| Документация | `docs/название` | только docs |
| Хотфикс | сразу в `main` | мелкие правки, конфиги |

---

## Структура коммитов

```
feat: краткое описание     ← новый функционал
fix: краткое описание      ← исправление бага
docs: краткое описание     ← документация
chore: краткое описание    ← служебное (зависимости, конфиги)
ci: краткое описание       ← CI/CD изменения
```

---

## Файлы которые нужно держать актуальными

| Файл | Когда обновлять |
|------|-----------------|
| `STATUS.md` | Каждую сессию — статус компонентов и план |
| `SESSION_LOG.md` | Конец каждой сессии — что сделано |
| `MOODLE_GUIDE.md` | При изменениях в Moodle инфраструктуре |
| `WORKFLOW.md` | При изменении процесса работы |
